# Project guidance

## Product and scope

- Build a standalone full-window calendar first. Google Calendar guides layout and interaction; `arkhivar/grist` supplies visual tokens, typography and suitable control patterns.
- Current milestone: local read/write Grist sandbox integration, explicitly authorized by the user. Keep the synthetic demo available and the data adapter independent of the calendar UI. Recurrence, Authentik, NetBird and Puppet deployment remain later work.
- Display and edit lesson times in `Asia/Vladivostok`; use explicit UTC ISO strings in the app and epoch seconds at the Grist boundary. Never use the browser's local timezone implicitly.
- Use `ALL_ATT` for lessons and attendance with stable `all-att:<row ID>` event identities. The user's current classification rule overrides the original import model: an empty `student` reference identifies a group lesson header; a student reference with empty `group2` identifies an individual lesson in that same row; a student reference with nonempty `group2` identifies attendance only, never another event. Do not retain the former indie/trial exception.
- Group attendance links to its header through the new `ALL_ATT.Calendar_Parent` self-reference. Individual attendance belongs to its own lesson row. Scheduling does not mark attendance: new calendar rows use `Calendar_Attendance=pending`. Attendance remains read-only in the UI. Cancellation preserves records. Manual checklist fractions remain manual.
- Existing lesson type, student references and group references are read-only in the editor and immutable through the save API. New lessons can be group headers or individual lessons with exactly one existing student and no group reference.
- Duplicate opens an unsaved lesson with copied scheduling details and manual checklist, a fresh identity, scheduled status and no attendance. Save creates the copy; never copy or reassign source attendance.
- Delete is a confirmed soft deletion: write only `ALL_ATT.Calendar_Status=deleted` and `Calendar_Mutation`, preserve the source row and all attendance links, and hide the event from calendar views. Failed/stale requests must not hide it; a stale editor must not resurrect it. Recovery currently uses a status change in Grist, with no in-app undo.
- `ALL_ATT.start`, `end` and `t` are the canonical schedule and teacher fields. The user explicitly authorizes updating those existing cells when editing a lesson. Preserve missing/multiple teacher references. Do not infer present/absent from payment values or notes.
- The editor offers 40/60/80-minute presets and custom end times. Editing Start preserves the current valid duration; editing End derives the duration without snapping. `Duration_Minutes` is a read-only Numeric formula using elapsed UTC minutes from start/end, blank for missing/invalid/nonpositive intervals. It is excluded from save projections and revisions. Preserve the existing guarded end trigger; direct Grist start-only edits retain a nonempty end.
- `Calendar_UID` is stored Text. A new-record-only `UUID()` default may fill missing IDs, but explicitly supplied calendar/preparation IDs must remain unchanged. Never use a regular recalculating UUID formula or regenerate existing preparation keys. `Calendar_Revision` and `Calendar_Mutation` retain their distinct concurrency/retry roles.
- `DateRegistry` holds one row per calendar date, with fixed calendar parity and manual school-day/holiday/term metadata. `ALL_ATT.Calendar_Date` derives from its own `start` in Asia/Vladivostok; `Transactions.Calendar_Date` derives from `datetime`. Keep `Calendar_Parent` for the specific lesson relationship. Missing or duplicate registry dates must not hide lessons; metadata and derived date links must not enter lesson revisions or save writes.
- Registry population is explicit, additive and idempotent; preserve manual metadata and all existing helper definitions. Only `School_Day=Closed` implies closure cues, never weekends or holiday text alone. Cues do not block scheduling. Current coverage is 2020–2029; extend it explicitly. Removing old date/day/hasDate helpers requires a later dependency review and decision.
- Explicit preparation groups attendance-only rows by exact `start` plus sorted `t` and `group2` references, reuses an unambiguous existing header or creates one, and adds `Calendar_Parent` links. New headers require valid, consistent source end times; do not invent a duration. Preserve original child scheduling values and all legacy links. Ordinary server startup never prepares data or adds schema.
- Moving a group header does not move its child attendance rows. An individual edit changes that row's authorized `start`/`end`/`t`; existing formulas and triggers may recalculate. Do not directly rewrite legacy `datetime`, `per`, notes, financial inputs or formula definitions, or promise formula-derived wages stay unchanged.
- The user removed `Calendar_Lessons`, `ALL_ATT.Calendar_Lesson` and `Calendar_Source_Revision` on 2026-10-15; do not recreate them. They are unused by the active adapter/default setup. The retained optional legacy migration flag targets the removed table and must not be used against this sandbox. Historical imports are not replayed.

## Data and authorization

- The user has authorized development access to a shared Grist sandbox. `ALL_ATT` means all attendance and is the main attendance table. Production currently uses SeaTable.
- The user explicitly permits adding new Grist columns when needed without asking again. **Do not delete existing columns or change existing column definitions.** Preserve existing values except the explicitly authorized lesson edits to `start`, `end` and `t`. Retain formulas and account for the parallel salaries project when testing writes. Use isolated fixtures or a test copy for destructive/automated scenarios. Later redundancy removal requires a separate decision after practical validation.
- Never commit credentials, real school records, private document URLs, logs containing personal information, `.env` files or document backups. Keep integration secrets server-side. A development service account is not the future teacher permission model.
- The reference repository is read-only. Reuse pinned, attributed pieces; do not load its moving main branch at runtime.

## Working and delivery

- Work locally, commit and push after each meaningful verified update (explicit user authorization). Use a `codex/` branch unless directed otherwise. Do not force-push.
- Keep documentation accurate about what is implemented, tested and pending. Do not claim a mocked write proves live Grist integration.
- Maintain `COLUMNS.md` as column decisions evolve. Distinguish implemented behavior, accepted changes, legacy cleanup candidates and proposals; record the reason and verification status without school data or credentials.
- Run meaningful tests for record identity, timezone conversion, failed saves, draft preservation and concurrency behavior. Test geometry-dependent dragging/resizing in a real browser; DOM-only tests do not establish that these work.
- Keep the first demo in memory with a visible Demo label and Reset control. Include a repeatable simulated failed-save path.
- Preserve accessibility: keyboard-operable controls and event alternatives, visible focus, labelled inputs, dialog focus management, reduced motion, readable overlap and narrow-screen behavior.
- No deployment is required for this local usability milestone. Authentik/Linux login can later be rolled out with the user's Puppet infrastructure.
